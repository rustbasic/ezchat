# guides/runtime.md

## 목적
이 문서는 현재 실행환경에 따른 제약과 가능 범위를 짧게 정리한다.

## 실행환경 종류
- `native`
- `wasm`

## 공통 원칙
- 현재 실행환경을 먼저 확인하고 그 범위 안에서만 행동한다.
- 실행환경에 맞지 않는 기능은 시도하지 않는다.
- 가능한 기능만 사용하고, 불가능한 기능은 설명으로 대체한다.

## `native` 환경
- 로컬 실행환경을 전제로 한다.
- 필요할 때 R-DOS 명령을 사용할 수 있다.
- 파일 확인, 콘솔 확인, 새 파일 저장 같은 보조 기능을 사용할 수 있다.
- 실제 로컬 상태를 바꿀 수 있는 작업은 신중하게 다룬다.

JSON 실행 예시:
```text
@rdos {"cmd":"rtype","file":"guides\\runtime.md"}
@rdos {"cmd":"console","count":80}
@rdos {"cmd":"rwrite","file":"tmp_demo.txt","content":"hello\n"}
```

- 읽기, 확인, 저장 같은 작업은 가능하면 내부 명령을 우선한다.
- 삭제나 영향 범위가 큰 작업은 먼저 사용자 확인을 받는다.

## `wasm` 환경
- 브라우저 또는 웹 제한 환경을 전제로 한다.
- 로컬 콘솔, 로컬 프로세스 실행, 로컬 파일 시스템 직접 접근은 제한되거나 불가능할 수 있다.
- 이 경우 명령 실행 대신 설명, 코드 제안, 절차 안내 중심으로 대응한다.

대응 예시:
- 실행 명령을 바로 제시하기보다 필요한 코드와 수정 방법을 설명한다.
- 사용자가 직접 반영할 수 있도록 patch 후보나 코드 블럭을 제공한다.

## 문서 참조 원칙
- R-DOS 규칙이 필요하면 `guides/rdos.md`를 참고한다.
- 파일 저장 규칙이 필요하면 `guides/file-save.md`를 참고한다.
- 모든 문서를 항상 읽을 필요는 없고, 현재 작업에 필요한 문서만 참고한다.

## 요약
- `native`: flat JSON 실행 예시 기반으로 실제 명령 사용 가능
- `wasm`: 실행보다 설명과 코드 제안 중심
- 현재 환경에 맞는 범위 안에서만 작업한다.
